# 独立上下文审计报告（三轮）

审计方式：把代码交给**全新上下文、未参与编写**的审计代理，只读、禁止修改文件，要求给出 `文件:行号` 级别的证据，并按 P0 / P1 / P2 分级。

- **P0**：功能不完整、崩溃、明显 bug、与需求不符 —— 必须修，修完要再开一轮审计
- **P1**：边界情况错误、设计缺陷、测试缺口 —— 应当修
- **P2**：风格、可读性、微小优化

第一、二轮为**代理独立审计**；第二轮结束后 **P0 = 0**，用户要求的"直到没有 P0 为止"条件达成。
第三轮为**提交后复跑的稳定性复核**（由我方驱动，非代理），针对端到端测试自身的确定性。

### 已修复的 P1 摘要

- **AI 卡住误判**：`moved < radius × 0.5` 与速度无关，被玩家的减速力场笼罩（速度减半）或体型变大时会误判为卡住并原地急转 → 改为与"本决策周期预期位移"比较。
- **逐帧新建渐变**：背景线性/径向渐变、竞技场内圈渐变每帧新建 —— 与"热路径零分配"自相矛盾 → 按主题 + 尺寸/半径缓存。
- **`prefers-reduced-motion` 未接入**：只杀了 CSS 动画，JS 侧的相机震屏与粒子照旧 → 系统偏好作为默认值，并让"减弱动效"真正关掉粒子与震屏/闪光。
- **死导出 / 死配置**：`easeOutCubic`、`easeInOutQuad`、`clearGlowCache` 从未被调用；`CONFIG.particles` 声称 1500/750/240 而实际硬编码 900/460/170（改配置完全无效）→ 删除死代码，粒子上限收敛为唯一来源。
- **重复实现**：`formatTime()` 在 `hud.js` 与 `screens.js` 各写一份；道具文案在 `main.js` 与 `hud.js` 各写一份 → 抽出 `core/format.js` 与 `POWERUP_INFO`。
- **`_respawnBot` 兜底不安全**：60 次尝试全失败会沿用最后一次随机点（可能落在陨石里）。
- **`#seg-theme` 主题值无白名单**：非法 theme 会让菜单没有任何高亮项 → 过白名单校验。
- **`isTouch` 被任意触摸永久置真**：触屏笔记本上"鼠标按住左键加速"会失效 → 改按当前指针类型判断。
- **`AudioContext` 构造未 try/catch**、**canvas `textAlign`/`textBaseline` 未复位**、**DPR 变化不触发 resize**、**`--muted` 对比度约 4.0:1 低于 WCAG AA**、**缺少 `user-select: none`**、**缺 `.gitignore`/`README.md`**、**根目录堆了 6 个自查日志**。

### 第二轮之后新增的防护网

审计反复证明"少写一个 `export`"这类问题**单元测试与 `node --check` 都抓不到，但会让整个模块图求值失败、页面白屏**。因此把 `tools/check-syntax.mjs` 从"只做语法检查"升级为"**语法 + 具名导入/导出链接**"双重检查：逐个解析 `import { a, b as c } from './x.js'` 并核对目标模块是否真的导出了这些名字。这一层在开发过程中真的拦下过 2 次白屏级错误。

## 第三轮：提交后重跑，揪出 1 个真实展示 bug + 3 处测试抖动

首次提交 `d638478` 之后按要求复跑冒烟，出现 **1 红**。**没有当成偶发跳过**，而是连跑统计，发现 4 次里红了 3 个**不同**的条目 —— 说明不是单点缺陷，而是"断言本身不确定"。

### 归因过程（先排除假设，再下结论）

1. 最像的假设是"自动暂停竞态"：`main.js` 在 `visibilitychange` 与 `window blur` 时会 `pause()`，无头环境截图/失焦可能误触发。挂上事件记录器重跑 6 次 → **`vis=[]`、blur 一次都没触发**，假设被排除。
2. 改写高频复现脚本（`.artifacts/probe.mjs`，共 30 轮"暂停→继续"，每 16ms 采样 `mode`）：**4/30 轮出现 `playing → over`**。结论明确 —— 暂停会把世界冻在半空，若蛇正在朝陨石/对手冲，**恢复后几百毫秒内死亡完全正常**，而原断言要求"恢复后仍存活"，等价于要求"这一局刚好没撞上东西"。

### 本轮确认的真实产品缺陷（P1）

| # | 问题 | 证据（修复前） | 根因 | 修复 |
| --- | --- | --- | --- | --- |
| 1 | **分数会以脏浮点直出给玩家** | `world.js:523` `const per = total / count`（宝石按"总价值 ÷ 球数"均分），`world.js:591` 再乘连击倍率；而 `hud.js:148`、`screens.js:136/149/150` 全部 `String(...)` 直出 → 面板可能出现 `73.33333333333333` | 展示层没有对内部浮点值取整 | 新增 `core/format.js` 的 `formatScore()`；HUD / 结算 / 主菜单最高分三处统一调用；`tests/format.test.js` 加 2 条回归测试 |

### 本轮修正的测试缺陷（不是产品的错）

| 断言 | 问题 | 改法 |
| --- | --- | --- |
| `可继续游戏` | 断言"蛇还活着"，依赖随机地形 → 抖动 | 改断言**机制**：轮询至 `mode !== 'paused'` 且 `elapsed` 前进。死亡同样证明世界已解冻，因此不再依赖运气 |
| `AI 对手数量符合难度预设` | 断言"此刻恰好存活 4 个"，而对手撞陨石后需延迟重生 | 快照新增配置常量 `botTarget`；改断言 `botTarget === 4 && 1 ≤ aliveBots ≤ botTarget` |
| `结算面板数值有效（soft）` | `/^\d+$/` 撞上浮点分数 | 由 `formatScore()` 从根上消除 |

> 教训：**端到端断言不能断言随机世界在某一时刻的具体态**，只能断言"机制/不变量"。第一、二轮关注"代码有没有实现功能"，这一轮补上的是"测试本身是否确定"。
